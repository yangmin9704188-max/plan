## 기획

### 누구를 위해

고객에게 청구하고 수금하는 인력사무소, 인테리어·철거·이사·설치·배관·전기 등 소규모 시공·용역업체, 그리고 두 업무를 겸하는 업체.

### 왜

인력사무소는 출역·공수·인건비를 모아 청구하지만, 시공·용역업체는 계약이나 견적을 바탕으로 인건비·자재·장비 내역을 청구한다. 지금은 시공·용역 방식의 청구를 쓰기 어렵고, 두 업무를 겸하는 업체는 같은 거래처·현장에서 청구할 대상과 받을 돈을 한곳에서 보지 못한다.

### 완성되면

- 인력 청구와 공사·용역 청구를 하나의 청구·수금 목록에서 관리하고, 거래마다 맞는 작성기로 작성한다
- 공사·용역은 품목분류·이름·규격·수량·단위·청구단가·고객용 비고로 내역을 쓰고 공급가액·부가세·이번 청구금액을 확인한다
- 소규모 작업은 긴 계약 등록 없이 간편 일괄청구로 끝낸다
- 계약의 계약금·중도금·잔금을 회차별로 청구한다
- 공사 초안을 저장해 두고 다시 열어 수정한다
- 미청구 후보액, 저장 초안, 청구미수금, 계약 선입금 잔액을 각각 확인한다
- 목록 조건·페이지를 유지한 채 작성·초안·청구 상세·계약 상세를 오간다

### 화면

업체 청구 → 청구·수금 / 계약·청구 일정

- 청구·수금: 청구 준비 / 청구 진행 / 청구 종결 탭, 전체 / 인력 청구 / 공사·용역 청구 유형 필터
- 1920px 화면에서 거래처명·현장명·작업자명·긴 품목명과 금액을 빠르게 읽을 수 있는 표 밀도

### 지켜야 할 규칙

- 회사 전체를 인력용·시공용으로 전환하지 않고 거래마다 유형을 구분한다
- 청구 준비의 한 행은 미청구 출역 묶음이나 미청구 계약 회차, 진행·종결의 한 행은 실제로 만든 청구건이다
- 인력 청구는 작업자명·근무일·공수·청구단가를 보존한다
- 계약 전체의 참고 내역과 이번 회차 금액, 업체 원가와 고객 청구가를 구분한다
- 초안 저장, 청구 생성, 발송, 수금은 서로 다른 단계다
- 청구한 명세는 고정한다. 잘못 만든 미발송 청구는 취소한 뒤 새 초안에서 다시 쓴다
- 중복 생성, 오래된 버전 덮어쓰기, 같은 출역의 이중 청구를 막는다
- 계약에 포함한 출역만 별도 인력 청구에서 빼고, 같은 현장의 별도 합의 출역은 빼지 않는다
- 기존 직접고용·직접지급·서류 전용 기준과 기초 이월 미수금을 그대로 유지한다
- 초안을 후보액에 더하거나 선입금을 청구미수금에서 자동으로 빼지 않는다. 선입금은 해당 계약의 실제 청구에만 연결한다
- 조회 조건 전체 합계와 현재 페이지 합계를 구분하고, 거래처 관리의 청구 잔액도 같은 기준으로 맞춘다. 거래처 요약은 '미청구·미수 합계'로 표시한다
- 청구 예정일과 입금기한을 나누고, 예정일을 입금기한으로 추정하지 않는다
- 기간 기준은 인력은 근무일, 공사는 청구 예정일, 진행은 청구 대상 기간, 종결은 종결일, 선입금은 입금일이다. 초안 보관에는 기간 필터를 적용하지 않는다
- 공사 준비에는 기본으로 도래한 회차와 예정일 미설정 회차를 보여주고, 미래 회차는 종료일을 지정해 조회한다
- 로딩·조회 실패를 0건·0원으로 보여주지 않고, 빈 목록·검색 결과 없음·저장 실패·버전 충돌·부분 수금·연체를 구분한다

### 이번에 안 하는 것

- 받은 청구서 접수·Gmail 연동·업체 지급 (별도 기능)
- 인력 청구의 영속 초안, 품목별 기성률 계산, 외부 견적 앱 연결, 복잡한 자재·원가관리, 서로 다른 방식의 청구서 합본
- 전자세금계산서 발행, 은행 자동 송금, 자동 세무 신고

## 확인 항목

- 정산센터 → 업체 청구 → 청구 준비에서 인력 출역과 공사·용역 회차가 같은 표에 나오고 유형·거래처·현장·청구 내용·준비금액을 구분할 수 있는지 확인한다.
- 업체 청구 → 전체·인력 청구·공사·용역 청구 필터를 차례로 눌러 목록과 건수·합계가 함께 바뀌는지 확인한다.
- 업체 청구 → 거래처·현장·검색 조건을 적용해 선택한 범위의 행과 금액만 표시되고 조건을 해제하면 원래 범위로 돌아오는지 확인한다.
- 청구 준비 → 기간을 지정해 인력은 근무일, 공사는 청구 예정일에 맞는 대상만 나오고 기간을 해제하면 예정일 미설정 회차도 다시 보이는지 확인한다.
- 청구 준비 → 미래 종료일을 지정해 미래 예정 회차를 찾을 수 있고, 청구 예정일과 입금기한이 서로 구분되는지 확인한다.
- 청구 준비·진행·종결 → 다음 페이지로 이동해 현재 페이지 합계는 바뀌어도 같은 조회 조건 전체 합계는 유지되는지 확인한다.
- 청구 준비 → 같은 거래처의 인력 현장을 선택해 청구 작성을 열고 작업자명·근무일·공수·단가와 선택한 기간이 유지되는지 확인한다.
- 인력 청구 작성 → 직접고용·직접지급·서류 전용 대상의 청구 근거와 금액이 기존 지급·수수료 설정에 맞는지 확인한다.
- 업체 청구 → 공사·용역 작성을 열어 품목분류·이름·규격·수량·단위·청구단가·비고를 입력하고 공급가액·부가세·청구금액을 확인한다.
- 공사·용역 작성 → 초안을 저장한 뒤 화면을 닫고 새로고침하여 초안 보관에서 다시 열었을 때 항목·수량·단가·비고가 유지되는지 확인한다.
- 청구 준비 → 초안 보관을 열어 저장 초안이 후보액·청구미수금에 중복 합산되지 않고 기간 필터의 적용 대상이 아니라는 설명이 보이는지 확인한다.
- 공사·용역 작성 → 청구 생성을 눌러 진행 목록에 실제 청구 한 건이 생기고 같은 원본을 다시 청구하려 할 때 중복 생성이 막히는지 확인한다.
- 계약·청구 일정 → 계약 회차의 청구 예정일과 입금기한을 다르게 저장한 뒤 다시 열어 두 날짜가 각각 유지되는지 확인한다.
- 계약 상세 → 계약금·중도금·잔금 회차의 청구 작성을 열어 계약 전체 참고 내역과 이번 회차 청구금액이 구분되는지 확인한다.
- 계약 상세 → 작업 근거를 계약 포함 또는 별도 합의로 연결한 뒤 청구 준비에서 포함한 출역만 제외되고 별도 합의 출역은 인력 청구 대상으로 남는지 확인한다.
- 공사 청구 상세 → 청구서 미리보기·PDF 저장 또는 인쇄·Excel 내려받기를 각각 실행해 품목·규격·수량·단가·세액·이번 청구금액이 저장한 명세와 일치하는지 확인한다.
- 생성한 공사 청구 상세 → 품목과 금액을 열어 확정한 명세가 읽기 전용으로 보이고 기존 청구를 직접 덮어쓸 수 없는지 확인한다.
- 미발송 청구 상세 → 취소 후 재작성을 진행해 기존 이력과 새 청구의 연결이 남고 같은 원본의 유효 청구가 중복되지 않는지 확인한다.
- 청구 진행 → 부분 수금·완납·종결을 차례로 처리해 받은 금액·남은 금액·단계가 맞게 바뀌고 수금된 청구의 부적절한 취소가 막히는지 확인한다.
- 계약 상세 → 선입금을 등록하고 해당 계약 청구에 배분해 잔액이 실제 배분 후 반영되며 다른 계약에 배분하거나 한도를 초과하는 처리가 막히는지 확인한다.
- 업체 청구의 거래처별 청구 잔액과 거래처 관리의 미수금을 비교해 같은 기준으로 맞고 미청구·미수 합계의 의미가 별도로 설명되는지 확인한다.
- 청구 진행·종결 → 전체 유형으로 조회해 기초 이월 미수금이 남아 있고 인력·공사 청구로 잘못 분류되지 않는지 확인한다.
- 필터와 페이지를 설정한 목록 → 청구 상세 또는 계약 상세 → 닫기·뒤로가기를 눌러 원래 조건과 문맥으로 돌아오며 직접 링크로 연 청구도 조회되는지 확인한다.
- 필터와 페이지를 설정한 청구 준비 → 공사·용역 작성 또는 저장 초안 → 닫기·뒤로가기를 눌러 원래 조회 조건과 페이지가 유지되는지 확인한다.
- 초안을 두 화면에서 열어 한쪽에서 먼저 저장한 뒤 다른 쪽에서 저장해 오래된 내용의 덮어쓰기가 막히고 수정 내용을 복구할 수 있는지 확인한다.
- 조회 결과가 없는 조건과 조회·저장 실패 상황에서 빈 결과·로딩·오류가 구분되고 재시도 안내와 입력 내용이 유지되는지 확인한다.
- 1920px 화면에서 긴 거래처·현장·작업자·품목명과 여러 행의 명세를 열어 이름·금액·기한·주요 버튼을 읽고 사용할 수 있는지 확인한다.
