## 기획

작업판 Office의 업체 청구를 인력사무소뿐 아니라 인테리어·철거·이사·설치·배관·전기 등 소규모 시공·용역업체도 사용할 수 있도록 확장한다. 인력사무소는 출역·공수·인건비를 모아 청구하고, 시공·용역업체는 계약이나 견적을 바탕으로 인건비·자재·장비 등의 내역을 청구한다. 두 업무를 겸하는 업체도 같은 거래처와 현장에서 청구할 대상과 받을 돈을 한곳에서 파악할 수 있어야 한다.

청구·수금 목록은 통합하고, 거래별 청구 근거에 따라 작성기와 상세 명세를 바꾼다. 회사 전체를 인력사무소용 또는 시공회사용으로 전환하는 구조는 사용하지 않는다. 업체 청구 안에는 `청구·수금 / 계약·청구 일정`을 두고, 청구·수금은 `청구 준비 / 청구 진행 / 청구 종결`과 `전체 / 인력 청구 / 공사·용역 청구` 유형 필터를 사용한다. 기존 기초 이월 미수금도 전체 진행·종결 목록에서 유지한다.

청구 준비의 한 행은 미청구 출역 묶음이나 미청구 계약 회차이고, 진행·종결의 한 행은 실제 생성한 청구건이다. 인력 작성에서는 작업자명·근무일·공수·청구단가를 보존한다. 공사·용역 작성에서는 품목분류·이름·규격·수량·단위·청구단가·고객용 비고를 저장하고 공급가액·부가세·이번 청구금액을 확인한다. 소규모 작업은 긴 계약 등록을 거치지 않고 간편 일괄청구를 작성할 수 있게 한다. 기존 계약의 계약금·중도금·잔금 청구는 계약 전체의 참고 내역과 이번 회차 금액을 구분한다. 업체의 원가와 고객에게 청구하는 가격도 구분한다.

공사 초안은 서버에 저장해 다시 열고 수정할 수 있어야 한다. 저장 초안, 청구 생성, 발송, 수금은 서로 다른 단계다. 청구한 명세는 고정하고, 잘못 만든 미발송 청구는 취소 후 명시적으로 새 초안에서 재작성한다. 중복 생성, 오래된 버전 덮어쓰기, 같은 출역의 이중 청구는 코드와 원본 관계로 막는다. 계약에 포함한 출역만 별도 인력 청구에서 제외하고, 같은 현장의 별도 합의 출역까지 제외하지 않는다. 기존 직접고용·직접지급·서류 전용 기준을 유지한다.

미청구 후보액, 저장 초안, 실제 청구미수금, 계약 선입금의 미배분 잔액은 각각 표시한다. 초안을 후보액에 더하거나 선입금을 청구미수금에서 자동 차감하지 않는다. 선입금은 해당 계약의 실제 청구에 연결하며 다른 계약에 잘못 배분되지 않게 한다. 조회 조건 전체 합계와 현재 페이지 합계를 구분하고, 거래처 관리의 청구 잔액도 같은 금액·수금 기준으로 맞춘다. 기존 거래처 요약이 미청구 출역과 청구 잔액을 함께 합산하는 의미는 유지하고 화면에서는 `미청구·미수 합계`로 설명한다.

청구 예정일과 입금기한을 분리한다. 기존 회차의 예정일을 입금기한으로 추정해 채우지 않는다. 준비 기간은 인력의 근무일과 공사의 청구 예정일을 기준으로 하고, 기본 공사 준비에는 도래한 회차와 예정일 미설정 회차를 보여 준다. 미래 회차는 미래 종료일을 지정해 조회한다. 진행·종결·선입금은 각각 청구 대상 기간·종결일·입금일 기준을 명시한다. 초안 보관에는 이 기간 필터를 적용하지 않는다.

사용자가 목록 조건·페이지를 유지한 채 작성·초안·청구 상세·계약 상세를 오갈 수 있게 한다. 로딩이나 조회 실패를 0건·0원으로 확정하지 않고, 빈 목록·검색 결과 없음·저장 실패·버전 충돌·부분 수금·연체를 구분한다. 1920px 화면에서 거래처명·현장명·작업자명·긴 품목명과 금액을 빠르게 읽을 수 있는 표 밀도를 우선한다.

PR01에서 공통 목록 구조를 정리하고, PR02에서 실제 저장·청구·출력이 가능한 내역형을 만든다. PR03에서 준비·집계·상태·화면 왕복을 통합하고 실제 사용 흐름과 출력 확인을 갖춘 뒤, PR04에서 확정한 Gemini 디자인을 적용한다. 진행 중인 정산·준비 화면 개편과 통합할 때도 양쪽 기능을 보존한다. Gemini에는 업무 맥락·필드·행동·예외·미지원 범위를 담은 자기완결 브리프와 같은 버전의 기준 화면을 전달한다. 코드 작성이나 문서 작성만으로 실제 화면 검증과 디자인 인계가 끝났다고 판단하지 않는다.

이 기능의 범위는 고객에게 청구하고 수금하는 업무다. 외부 청구서 접수·Gmail 연동·업체 지급은 별도 기능으로 관리한다. 인력 청구의 영속 초안, 품목별 기성률 계산, 외부 견적 앱 연결, 복잡한 자재·원가관리, 서로 다른 방식의 청구서 합본은 후속 범위다. 전자세금계산서 발행·은행 자동 송금·자동 세무 신고를 이번 기능의 완료 동작으로 표시하지 않는다.

개발 중 PR 분할·통합·순서·대상 저장소·실제 브랜치가 바뀌면 이 파일의 개발 계획을 함께 갱신한다. 파일명은 기능 ID로 유지하고, 이미 확인한 항목의 문장은 의미가 바뀌는 경우에만 수정한다. PR 상태는 GitHub 연결로 확인하며 최종 기능 완료와 화면 확인 결과는 대표가 직접 판단한다.

## 확인 항목

- 정산센터 → 업체 청구 → 청구 준비에서 인력 출역과 공사·용역 회차가 같은 표에 나오고 유형·거래처·현장·청구 내용·준비금액을 구분할 수 있는지 확인한다.
- 업체 청구 → 전체·인력 청구·공사·용역 청구 필터를 차례로 눌러 목록과 건수·합계가 함께 바뀌는지 확인한다.
- 업체 청구 → 거래처·현장·검색 조건을 적용해 선택한 범위의 행과 금액만 표시되고 조건을 해제하면 원래 범위로 돌아오는지 확인한다.
- 청구 준비 → 기간을 지정해 인력은 근무일, 공사는 청구 예정일에 맞는 대상만 나오고 기간을 해제하면 예정일 미설정 회차도 다시 보이는지 확인한다.
- 청구 준비 → 미래 종료일을 지정해 미래 예정 회차를 찾을 수 있고, 청구 예정일과 입금기한이 서로 구분되는지 확인한다.
- 청구 준비·진행·종결 → 다음 페이지로 이동해 현재 페이지 합계는 바뀌어도 같은 조회 조건 전체 합계는 유지되는지 확인한다.
- 청구 준비 → 같은 거래처의 인력 현장을 선택해 청구 작성을 열고 작업자명·근무일·공수·단가와 선택한 기간이 유지되는지 확인한다.
- 인력 청구 작성 → 직접고용·직접지급·서류 전용 대상의 청구 근거와 금액이 기존 지급·수수료 설정에 맞는지 확인한다.
- 업체 청구 → 공사·용역 작성을 열어 품목분류·이름·규격·수량·단위·청구단가·비고를 입력하고 공급가액·부가세·청구금액을 확인한다.
- 공사·용역 작성 → 초안을 저장한 뒤 화면을 닫고 새로고침하여 초안 보관에서 다시 열었을 때 항목·수량·단가·비고가 유지되는지 확인한다.
- 청구 준비 → 초안 보관을 열어 저장 초안이 후보액·청구미수금에 중복 합산되지 않고 기간 필터의 적용 대상이 아니라는 설명이 보이는지 확인한다.
- 공사·용역 작성 → 청구 생성을 눌러 진행 목록에 실제 청구 한 건이 생기고 같은 원본을 다시 청구하려 할 때 중복 생성이 막히는지 확인한다.
- 계약·청구 일정 → 계약 회차의 청구 예정일과 입금기한을 다르게 저장한 뒤 다시 열어 두 날짜가 각각 유지되는지 확인한다.
- 계약 상세 → 계약금·중도금·잔금 회차의 청구 작성을 열어 계약 전체 참고 내역과 이번 회차 청구금액이 구분되는지 확인한다.
- 계약 상세 → 작업 근거를 계약 포함 또는 별도 합의로 연결한 뒤 청구 준비에서 포함한 출역만 제외되고 별도 합의 출역은 인력 청구 대상으로 남는지 확인한다.
- 공사 청구 상세 → 청구서 미리보기·PDF 저장 또는 인쇄·Excel 내려받기를 각각 실행해 품목·규격·수량·단가·세액·이번 청구금액이 저장한 명세와 일치하는지 확인한다.
- 생성한 공사 청구 상세 → 품목과 금액을 열어 확정한 명세가 읽기 전용으로 보이고 기존 청구를 직접 덮어쓸 수 없는지 확인한다.
- 미발송 청구 상세 → 취소 후 재작성을 진행해 기존 이력과 새 청구의 연결이 남고 같은 원본의 유효 청구가 중복되지 않는지 확인한다.
- 청구 진행 → 부분 수금·완납·종결을 차례로 처리해 받은 금액·남은 금액·단계가 맞게 바뀌고 수금된 청구의 부적절한 취소가 막히는지 확인한다.
- 계약 상세 → 선입금을 등록하고 해당 계약 청구에 배분해 잔액이 실제 배분 후 반영되며 다른 계약에 배분하거나 한도를 초과하는 처리가 막히는지 확인한다.
- 업체 청구의 거래처별 청구 잔액과 거래처 관리의 미수금을 비교해 같은 기준으로 맞고 미청구·미수 합계의 의미가 별도로 설명되는지 확인한다.
- 청구 진행·종결 → 전체 유형으로 조회해 기초 이월 미수금이 남아 있고 인력·공사 청구로 잘못 분류되지 않는지 확인한다.
- 필터와 페이지를 설정한 목록 → 청구 상세 또는 계약 상세 → 닫기·뒤로가기를 눌러 원래 조건과 문맥으로 돌아오며 직접 링크로 연 청구도 조회되는지 확인한다.
- 필터와 페이지를 설정한 청구 준비 → 공사·용역 작성 또는 저장 초안 → 닫기·뒤로가기를 눌러 원래 조회 조건과 페이지가 유지되는지 확인한다.
- 초안을 두 화면에서 열어 한쪽에서 먼저 저장한 뒤 다른 쪽에서 저장해 오래된 내용의 덮어쓰기가 막히고 수정 내용을 복구할 수 있는지 확인한다.
- 조회 결과가 없는 조건과 조회·저장 실패 상황에서 빈 결과·로딩·오류가 구분되고 재시도 안내와 입력 내용이 유지되는지 확인한다.
- 1920px 화면에서 긴 거래처·현장·작업자·품목명과 여러 행의 명세를 열어 이름·금액·기한·주요 버튼을 읽고 사용할 수 있는지 확인한다.
