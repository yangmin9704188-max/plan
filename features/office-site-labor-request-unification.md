## 기획

### 누구를 위해

현장에 필요한 건설 일용근로자를 요청하는 업체와, 인력을 소개하고 출역·임금·소개료를 관리하는 인력사무소를 위한 기능이다.

### 왜

현장 등록에 이미 있는 단가·수수료·지급·신고 조건을 요청서에 다시 만들면 같은 거래의 금액과 책임이 달라진다.
현장 기본값과 상대가 합의한 조건을 구분하고, 소개료·임금 대리정산 원금·세금을 같은 기준으로 계산해야 양측 정산이 맞는다.
등록 화면과 서버의 필수값도 서로 다르다. 상대방 유형을 먼저 구분하고 저장·구인 장부·지급·법정 증빙에
필요한 정보를 각각 연결해야 불필요한 입력을 줄이면서 뒤의 정산과 서류가 같은 근거로 만들어진다.

### 완성되면

- 거래처는 유형을 직접 선택해 최소 정보로 저장하고, 번호가 없어도 유형을 유지하며 현장의 누락 배지와 문서의 빈칸으로 확인한다.
- 대불·직불·직고용과 지난 조건을 불러오고, 업체 총액 또는 근로자 세전 임금 중 편한 방식으로 같은 거래조건을 입력한다.
- 보험은 거래처 처리·우리 쪽 처리·세무/노무 담당자 전달 중 고르고 필요한 상세정보만 해당 업무에서 보완한다.
- 전화·문자의 외부 합의와 앱에서 수락한 조건을 구분하며, 기본값을 바꿔도 이미 합의한 조건과 확정 정산을 유지한다.
- 수락한 사무소의 현장과 요청업체의 지급 예정이 연결되고 실제 출역·대불·소개료를 근거로 중복 없이 정산한다.
- 화면과 자쿠에서 같은 업무 경로의 계산 결과·출처·다음 행동을 안내받고 상세 근거는 필요할 때 펼친다.

### 화면

Office → 거래처·현장 → 거래처 등록 / 현장 등록 / 현장별 거래조건.

Office → 견적 → 승인 견적의 현장 등록.

인력사무소 요청·수신 요청에서 사무소 선택, 조건 제안, 수정안, 수락 결과를 제공한다.
입력은 거래 상대 → 보유 문서정보·연락 → 현장·업무 패턴/지난 조건 → 날짜별 작업·총액 또는 세전 임금 →
보험 업무 처리·업체 정산 순서다. 기본값이 있으면 적용값과 출처를 먼저 보여주고 필요한 것만 보완한다.
표에서는 대불·직불·직고용 배지를 유지하고 선택 화면과 도움말에 한 문장 설명을 붙인다.
세부 메뉴 위치와 시각적 배치는 공통 조건을 적용하는 화면 작업에서 정한다.

Office → 관제·출역, 정산센터 → 업체 청구 / 업체 지급의 예정·내부 산출·정산·지급으로 연결한다.

### 지켜야 할 규칙

상세 입력·법령·계산·서류 관계는 [등록에서 정산·서류까지](https://github.com/yangmin9704188-max/jakupan_office_web/blob/codex/office-site-labor-terms-20261124/docs/OFFICE_REGISTRATION_SETTLEMENT_PIPELINE.md)를 따른다.

- 개인사업자·법인사업자·비사업자 개인은 기본값 없이 선택한다. 법인 선택 후 국내를 기본으로 보여주고 외국으로 변경할 수 있다. 번호가 없는 사업을 비사업자로 자동 분류하지 않는다.
- 사업자번호가 없으면 사업자인 거래처·현장에 누락 배지를 표시하고 일반 문서는 공란으로 출력한다. 외부 인증·등록증 진위 심사·별도 승인 단계를 추가하지 않는다.
- 기본 저장, 실제 구인접수 사실, 장부 완성, 합의, 지급, 문서 발급은 준비 조건이 다르다. 부족한 정보 때문에 이미 발생한 접수·출역·지급 사실을 지우지 않는다.
- 현장 담당자 이름·휴대전화는 기본 선택이다. 구인접수대장의 구인자 전화번호는 별도로 보완하고 같은 번호를 재사용할 수 있다.
- 주민번호는 일반 거래처 등록에 넣지 않고 해당 법정 세무 업무의 보안 경로에서만 받는다. 공식 상호·실제 주소·표시명을 구분하고 개인 주소·이메일도 보존한다.
- 첫 사무소 요청은 국내 사업자 요청업체가 실제 고용주이고 등록 사무소가 소개하는 건설 일용근로자 고용알선이다. 사무소 고용 인력의 파견·공급·공사도급으로 자동 전환하지 않는다.
- 거래처·현장 등록, 외부 합의 기록, 앱의 상대방 수락은 서로 다른 사건이다. 내부 등록을 상대방의 동의로 표시하지 않는다.
- 현장 기본 인원과 이번 요청의 날짜·직종별 인원, 수락 인원, 배정 인원, 실제 출역 인원을 구분한다.
- 근로자 세전 임금과 사무소 소개료를 구분한다. 건설 소개료 상한은 임금의 10%이며 임금+소개료 총액의 10%가 아니다. 적용 고용기간의 상한을 유지한다.
- 총액 입력과 세전 임금 입력은 같은 계산을 사용한다. 총액18만원·임금 기준 소개료10%이면 세전 임금163,637원과 소개료16,363원으로 나눈다.
- 기본 총액에는 사업주 보험료 별도를 명시한다. 보험료까지 포함한 예산은 미정 보험료를0원으로 숨기지 않고, 이미 합의한 근로자 임금을 나중에 자동 감액하지 않는다.
- 직업소개료는 부가세 면세다. 증명된 임금 대리정산 원금은 사무소 공급대가에서 제외한다. 일반과세자 등록만으로 소개료에 부가세를 붙이지 않는다.
- 국내 개인 사무소의 소개료는 지급자 요건에 따라 사업소득 원천징수하고, 내국법인 사무소에는 해당 공제를 적용하지 않는다. 근로자 임금과 대불원금에 소개료의 원천세를 적용하지 않는다.
- 고용주, 임금 의무자, 실제 송금자, 법정 신고 의무자, 실무 대행자를 구분한다. 사무소가 대불했다고 고용주가 바뀌지 않는다.
- 4대보험 제외를 합의하는 스위치를 만들지 않는다. 보험별 법정 적용을 실제 고용·기간·사업장 사실로 판단하고 산재보험료를 근로자에게 공제하지 않는다.
- 합의한 식사·교통·숙박의 제공자·부담자·금액·증빙을 명시한다. 관리비 등 이름을 붙여 소개료 한도를 우회하지 않는다.
- 청구일, 업체 지급기일, 근로자 임금일을 각각 보존한다. 회사 기본값은 새 초안에 적용하고 발송·수락 버전을 덮어쓰지 않는다.
- 단가 미정의 인원 협의를 금액이 확정된 계약 수락으로 만들지 않는다. 작업자·등급별 단가 또는 적용 가격표를 합의한 뒤 확정한다.
- 수락 시 업체 지급에는 예정만 연결한다. 실제 출역·비용·지급 없이 채무와 대불회수를 확정하지 않는다.
- 동일 요청을 재시도하거나 동시에 수락해도 현장·합의·지급 예정·채무를 중복 생성하지 않는다. 한쪽 연결 실패는 연결 중 상태로 재처리한다.
- 기존 확정 금액과 과거 기록을 추정으로 재계산하거나 앱 수락 완료로 바꾸지 않는다.
- 실제 근로자 선정 전에도 등급별 단가표와 적용 규칙이 합의되면 수락할 수 있다. 최종 근무금액 미정과 단가 결정 규칙 미정을 구분한다.
- 일별 예상 세액과 지급 때의 소액부징수 결과를 구분한다. 같은 실제 지급을 화면 요청만 나눠 다른 세무 단위로 만들지 않는다.
- 보험의 법적 역할은 내부에서 구분하고 처음부터 다섯 질문으로 받지 않는다. 업무 처리 패턴이 법적 책임·가입 여부를 자동 변경하지 않는다.
- 자쿠는 자연어 의도와 입력을 기존 업무 경로에 연결하고 서버의 결과·다음 행동을 설명한다. 저장된 사실을 다시 묻거나 임금·세금·채무를 모델이 새로 계산하지 않는다.
- 사용자에게 보일 기본 안내는 짧은 규칙 문구로 제공하고 매 입력마다 LLM을 호출하지 않는다. 개인 식별정보 원문을 외부 모델에 보내지 않는다.

### 이번에 안 하는 것

- 패널의 시각적 배치·색상·디자인 확정.
- 전사 공용 현장 마스터나 범용 계약 시스템 신설.
- 과거 거래 전체의 합의·세금 분류 자동 이관.
- 파견·독립 공사도급·허가 근로자공급 요청 기능.
- 모바일 화면 구현 및 기기 검증.
- 공단 신고·국세청 발급·은행 송금의 자동 실행.
- 국제세무 전용 등록 양식·조약 자동 판정·외부 사업자 진위 인증.

## 확인 항목

- 견적 → 승인 견적에서 현장 등록 → 인력 청구 부가세 포함 또는 별도를 선택하면 생성한 현장의 정산 기본값에 같은 값이 남는다.
- 견적 → 동일 현장 등록을 다시 시도하면 같은 현장을 보여 주고 현장과 VAT 설정이 중복 생성되지 않는다.
- 현장 등록 → 임금 160,000원과 소개료 10%를 입력하면 임금 160,000원, 소개료 16,000원, 합계 176,000원이 보인다.
- 현장 조건 → 임금과 소개료 합계 160,000원에서 소개료 16,000원을 떼려고 하면 법정 임금 기준 한도 초과로 확정되지 않는다.
- 거래조건 → 일반과세자로 등록된 사무소의 직업소개 거래도 소개료가 면세로 표시되고 대불원금은 매출과 분리된다.
- 업체 지급 → 개인 사무소 소개료와 내국법인 사무소 소개료에서 원천징수 여부가 다르게 계산되고 임금 대불원금에는 해당 공제가 붙지 않는다.
- 현장 등록 → 외부 합의를 기록하면 기록자와 적용 조건이 남으며 상대방의 앱 수락으로 표시되지 않는다.
- 인력 요청 → 5명 요청에 3명 수정안을 보내고 상대가 수락하면 요청 5명과 합의 3명이 각각 남는다.
- 인력 요청 → 수락하면 수신 사무소 현장이 생성·연결되고 요청업체의 업체 지급에는 예정으로만 나타난다.
- 같은 현장의 추가 요청 → 기존 수신 현장을 재사용하면서 각 요청의 조건과 인원이 따로 유지된다.
- 회사 기본값 → 소개료나 지급방식을 바꿔도 이미 수락한 요청의 조건과 확정 정산이 바뀌지 않는다.
- 업체 지급 → 실제 출역과 증명된 대불을 연결한 뒤 정산하면 동일 임금 원금이 작업자 지급과 업체 지급에 중복 반영되지 않는다.
- 현장 조건 → 가입 판정 자료가 부족한 보험은 미확정으로 표시하고 산재보험료를 근로자 공제로 넣지 않는다.
- 거래처 등록 → 담당자 연락처 없이 기본 정보를 저장 → 저장은 되고 실제 구인 장부에 필요한 구인자 전화번호의 보완 위치가 보인다.
- 개인 거래처 → 실제 주소와 이메일 입력 후 다시 열기 → 표시명으로 바뀌거나 사라지지 않는다.
- 거래처 문서정보 → 표시명과 공식 상호를 다르게 저장 → 법정 문서는 공식 당사자 정보로 준비된다.
- 실제 구인접수 → 주소나 허가정보가 미비한 요청을 기록 → 실제 접수일과 원천은 남고 장부 미비 항목이 구분된다.
- 인력 요청 → 근로자를 고르기 전에 확정 등급별 단가표로 요청·수락 → 현장과 단가 기준 지급 예정이 연결되고 확정 채무는 생기지 않는다.
- 업체 지급 → 임금 160만원·확정 근로자 공제 4만원·개인 사무소 소개료 16만원인 직불 거래 확인 → 근로자 156만원, 사무소 154,720원, 근로자 공제 4만원, 소개료 원천세 5,280원이 구분된다.
- 근로자 지급 → 과세 일급 18만원 이틀분을 한 번에 지급 → 일별 예상값이 0원이어도 지급단위 소득세는 1,620원으로 계산된다.
- 자쿠 → 특정 현장의 소개료와 송금액 이유 질문 → 해당 합의·상속 출처와 계산 성분을 설명하고 기록된 내용을 다시 묻지 않는다.
- 대불 정산 → 고객이 미리 맡긴 임금 자금으로 근로자에게 지급 → 실제 집행 후에도 같은 금액이 대불 상환 채무로 다시 잡히지 않는다.
- 거래처 등록 → 첫 유형이 선택되지 않은 상태에서 법인사업자를 선택 → 국내가 기본으로 표시되고 외국으로 바꿔 저장할 수 있는지 확인한다.
- 사업자인 거래처를 사업자번호 없이 저장하고 연결 현장을 열기 → 유형이 유지되고 사업자정보 미입력 배지가 보이며 비사업자 개인에게는 같은 배지가 붙지 않는지 확인한다.
- 사업자번호가 없는 거래처의 일반 청구서·거래명세 출력 → 해당 칸은 빈칸이고 외부 인증이나 새 승인 절차 없이 출력할 수 있는지 확인한다.
- 현장 금액 입력 → 업체 총액180,000원과 임금 기준 소개료10% 입력 → 세전 임금163,637원·소개료16,363원이 보이고 세전 임금180,000원 모드에서는 합계198,000원이 보이는지 확인한다.
- 현장 금액 입력 → 사업주 보험료도 예산에 포함을 선택하고 미정인 보험 자료를 남겨 저장 → 예상과 확정이 구별되고 이후 보험료 변경이 이미 합의한 임금을 자동으로 낮추지 않는지 확인한다.
- 현장 등록 → 보험 업무를 거래처 처리 또는 세무·노무 담당자 전달로 선택 → 법적 역할 다섯 개와 모든 관리번호를 입력하지 않아도 저장되고 해당 업무에서 필요한 정보만 안내되는지 확인한다.
- 현장 등록 → 지난 조건 불러오기 → 총액/세전 입력·소개료·마감일·식사 조건과 출처가 표시되고 이전 현장과 이미 합의한 거래가 바뀌지 않는지 확인한다.
- 정산 목록 → 대불·직불·직고용 배지에 호버·키보드 포커스 또는 클릭 → 짧은 배지는 유지되고 실제 지급·고용 의미를 한 문장으로 확인할 수 있는지 확인한다.
- 자쿠 → 이미 저장된 현장 조건의 금액 근거를 질문 → 같은 업무 서비스의 결과로 답하고 알려진 정보를 다시 묻거나 새로 계산하지 않으며 현재 지원하지 않는 금전 실행은 해당 화면으로 연결되는지 확인한다.
