## 기획

### 누구를 위해

현장에 필요한 건설 일용근로자를 요청하는 업체와, 인력을 소개하고 출역·임금·소개료를 관리하는 인력사무소를 위한 기능이다.

### 왜

현장 등록에 이미 있는 단가·수수료·지급·신고 조건을 요청서에 다시 만들면 같은 거래의 금액과 책임이 달라진다.
요청할 사무소를 미리 알고 있지 않아도 현장 주변의 사무소와 실제 충원 실적을 비교하고,
직접 조건을 제안하거나 모집 공고로 지원을 받아 선택할 수 있어야 한다.
현장 기본값과 상대가 합의한 조건을 구분하고, 소개료·임금 대리정산 원금·세금을 같은 기준으로 계산해야 양측 정산이 맞는다.
등록 화면과 서버의 필수값도 서로 다르다. 상대방 유형을 먼저 구분하고 저장·구인 장부·지급·법정 증빙에
필요한 정보를 각각 연결해야 불필요한 입력을 줄이면서 뒤의 정산과 서류가 같은 근거로 만들어진다.

### 완성되면

- 거래처 유형·지난 조건을 불러와 최소 정보로 저장하고, 총액/세전 임금·직불/대불·보험 처리 방식은 현장과 요청에서 같은 기준으로 입력한다. 누락값은 배지·문서 공란으로 확인하고 필요한 업무에서 보완한다.
- 현장 기준 반경 N km의 인력사무소와 최근 90일 확인 충원율·표본·미확인 실적을 비교해 요청할 사무소를 고른다.
- 선택한 사무소에 계약조건을 직접 보내거나 인력사무소 모집 공고를 게시해 지원을 받는다. 지원 조건과 실적을 비교하고 남은 인원 안에서 여러 사무소를 선정한다.
- 받은 요청·보낸 요청에서 수정안을 비교하고 수락하며, 현장·거래처·요청 상세에서 같은 계약과 합의 확인서를 다시 연다. 전화·문자의 외부 합의와 앱 수락을 구분한다.
- 수락한 사무소의 현장과 요청업체의 지급 예정이 연결되고 실제 출역·대불·소개료를 근거로 청구·받은 청구·지급 내역서를 주고받는다. 기지급·수금·반환을 같은 거래에 연결한다.
- 화면과 자쿠에서 같은 업무 경로의 계산 결과·출처·다음 행동을 안내받고 상세 근거는 필요할 때 펼친다.

### 화면

Office → 거래처·현장 → 거래처 등록 / 현장 등록 / 현장별 거래조건.

Office → 견적 → 승인 견적의 현장 등록.

**거래처·현장 → 인력사무소 요청**에서 요청업체는 **사무소 찾기 / 보낸 요청 / 내 모집 공고**를,
공급 사무소는 **모집 공고 / 내 지원 / 받은 요청**을 사용한다. 같은 회사가 양쪽 업무를 할 수 있다.
**내 모집 공고 → 지원 사무소 보기**에서 실적·가능 인원·제안 조건을 비교하고 **이 조건으로 선정·수락**한다.
관제센터·현장 상세의 **인력 요청**은 현재 현장을 채운 같은 작성 화면으로 연결한다.
현장 상세의 **요청 내역**, 거래처 상세의 연결 현장에서도 해당 현장·상대의 요청을 바로 연다.

요청 모달은 **요청 대상·현장 → 필요한 인력 → 계약조건 → 검토·발송**의 4단계다.
첫 단계에서 **사무소 찾아 요청 / 인력사무소 모집 공고**를 선택한다. 직접 요청은 선택 현장을 중심으로
반경 N km의 사무소·최근 90일 확인 충원율·집계 표본을 보고 선택하고, 공개코드는 보조 찾기 수단으로 둔다.
사무소를 찾지 않고 공고를 내면 사무소가 **지원하기**로 가능한 인원과 조건을 제안한다.
마지막 버튼은 경로에 따라 **계약조건 보내기 / 모집 공고 게시**다.
날짜별 인원·직종·시간, 총액 또는 세전 임금·소개료·직불/대불·근로자 지급일,
보험 업무 처리·부대비용·업체 정산 일정·수락기한을 같은 조건 입력으로 연결한다.
현장 조건·지난 조건을 불러오고 이번 요청에서 바뀐 항목을 보여준다. 사용자가 합의 버전 숫자를 입력하지 않는다.
요청 상세에서 **이 조건으로 수락 / 조건 변경 제안 / 거절**을 제공하고 수정된 항목을 비교한다.

**현장 상세 → 계약조건 → 사무소별 합의**, 요청 상세의 **계약 보기**, 거래처의 연결 현장 **계약 보기**는
같은 수락 계약과 합의 확인서를 연다. 개인 Worker 근무 요청·근로계약 서명은 별도 업무로 유지한다.

공급 사무소는 요청 상세의 **인력 배정 / 청구 준비·청구 보기**에서 기존 관제·업체 청구로,
요청업체는 **지급 보기**에서 기존 업체 지급의 계획·산출 / 접수·검토 / 정산 검토 / 지급 관리로 이동한다.
같은 계약의 청구서 발송 원본, 받은 청구, 정산 거래 명세, 지급 내역과 상대 수금 확인을 연결해서 본다.

### 지켜야 할 규칙

상세 입력·계산·서류 관계는 [등록에서 정산·서류까지](https://github.com/yangmin9704188-max/jakupan_office_web/blob/codex/office-agency-flow-docs-20261125/docs/OFFICE_REGISTRATION_SETTLEMENT_PIPELINE.md),
요청 모달·버튼·계약·양측 문서는 [공통 업무 계약](https://github.com/yangmin9704188-max/jakupan_office_web/blob/codex/office-agency-flow-docs-20261125/docs/OFFICE_SITE_LABOR_REQUEST_UNIFICATION_SPEC.md)을 따른다.

- 개인사업자·법인사업자·비사업자 개인은 기본값 없이 선택한다. 법인 선택 후 국내를 기본으로 보여주고 외국으로 변경할 수 있다. 번호가 없는 사업을 비사업자로 자동 분류하지 않는다.
- 사업자번호가 없으면 사업자인 거래처·현장에 누락 배지를 표시하고 일반 문서는 공란으로 출력한다. 외부 인증·등록증 진위 심사·별도 승인 단계를 추가하지 않는다.
- 기본 저장, 실제 구인접수 사실, 장부 완성, 합의, 지급, 문서 발급은 준비 조건이 다르다. 부족한 정보 때문에 이미 발생한 접수·출역·지급 사실을 지우지 않는다.
- 현장 담당자 이름·휴대전화는 기본 선택이다. 구인접수대장의 구인자 전화번호는 별도로 보완하고 같은 번호를 재사용할 수 있다.
- 주민번호는 일반 거래처 등록에 넣지 않고 해당 법정 세무 업무의 보안 경로에서만 받는다. 공식 상호·실제 주소·표시명을 구분하고 개인 주소·이메일도 보존한다.
- 첫 사무소 요청은 국내 사업자 요청업체가 실제 고용주이고 등록 사무소가 소개하는 건설 일용근로자 고용알선이다. 사무소 고용 인력의 파견·공급·공사도급으로 자동 전환하지 않는다.
- 사무소 탐색의 거리는 선택한 현장과 저장된 사무소 좌표를 기준으로 한다. 좌표 없는 사무소를 0 km로 표시하거나 화면을 열 때마다 외부 주소 변환을 실행하지 않는다.
- 사무소가 기본 꺼짐인 B2B 탐색 노출을 직접 켜야 후보에 보인다. 기존 공개 프로필·좌표의 이름·공개코드·분야·거리만 사용하고 개인 연락처·상대 tenant ID·정확한 좌표는 공개하지 않는다.
- 최근 90일 확인 충원율은 한국시간 어제까지 확정 수락한 약속 인원 대비 확인 출역 인원의 하한값이다. worker·shift 중복과 약속 인원 상한을 적용하며 표본 요청 수·약속/확인 인원·기간·기준시각을 함께 보인다. 수락 표본·출역 근거가 없으면 비율 없이 자료 부족, 일부만 확인됐으면 비율과 미확인 실적 포함을 표시한다. 실제 전체 충원 성적을 확정한 평점으로 표현하지 않는다.
- 직접 제안과 모집 공고 지원은 같은 요청·제안·수락 원본으로 연결한다. 개인 근로자 모집·B2C 시공사 소개와 구분하며 공고 게시·지원만으로 계약·현장·PAY 예정이 생기지 않는다.
- 같은 원 수요의 날짜·직종·근무조별 남은 인원 안에서 여러 사무소를 선정한다. 직접 제안과 공고를 함께 사용하거나 동시에 수락해도 초과 충원하지 않고, 지원 인원을 줄일 때는 그 조건을 상대와 다시 합의한다.
- 공고 수정·지원 수정·철회·미선정·모집 마감·만료는 과거 조건·수락 계약·출역·청구·지급을 지우지 않는다. 마감·만료 뒤에는 새 지원과 대기 제안 수락을 닫는다. 다른 사무소의 지원 원문과 내부 현장 메모는 공개하지 않는다.
- 공고에 가정한 사무소 유형과 실제 지원 사무소 유형이 다르면 실제 등록 유형으로 같은 가격 입력을 재계산한 수정 조건을 제시하고 그 버전을 명시적으로 수락한다. 유형만 다르다는 이유로 지원을 차단하지 않는다.
- 요청별 가격 입력·적용기간·임금 지급·보험 처리의 변경은 서버가 계산한 전체 유효 조건 snapshot으로 불변 제안 버전에 저장하며 현장 기본값을 덮어쓰지 않는다.
- 거래처·현장 등록, 외부 합의 기록, 앱의 상대방 수락은 서로 다른 사건이다. 내부 등록을 상대방의 동의로 표시하지 않는다.
- 현장 기본 인원과 이번 요청의 날짜·직종별 인원, 수락 인원, 배정 인원, 실제 출역 인원을 구분한다.
- 근로자 세전 임금과 사무소 소개료를 구분한다. 건설 소개료 상한은 임금의 10%이며 임금+소개료 총액의 10%가 아니다. 적용 고용기간의 상한을 유지한다.
- 총액 입력과 세전 임금 입력은 같은 계산을 사용한다. 총액18만원·임금 기준 소개료10%이면 세전 임금163,637원과 소개료16,363원으로 나눈다.
- 기본 총액에는 사업주 보험료 별도를 명시한다. 보험료까지 포함한 예산은 미정 보험료를0원으로 숨기지 않고, 이미 합의한 근로자 임금을 나중에 자동 감액하지 않는다.
- 직업소개료는 부가세 면세다. 증명된 임금 대리정산 원금은 사무소 공급대가에서 제외한다. 일반과세자 등록만으로 소개료에 부가세를 붙이지 않는다.
- 국내 개인 사무소의 소개료는 지급자 요건에 따라 사업소득 원천징수하고, 내국법인 사무소에는 해당 공제를 적용하지 않는다. 근로자 임금과 대불원금에 소개료의 원천세를 적용하지 않는다.
- 고용주, 임금 의무자, 실제 송금자, 법정 신고 의무자, 실무 대행자를 구분한다. 사무소가 대불했다고 고용주가 바뀌지 않는다.
- 4대보험 제외를 합의하는 스위치를 만들지 않는다. 보험별 법정 적용을 실제 고용·기간·사업장 사실로 판단하고 산재보험료를 근로자에게 공제하지 않는다.
- 합의한 식사·교통·숙박의 제공자·부담자·금액·증빙을 명시한다. 관리비 등 이름을 붙여 소개료 한도를 우회하지 않는다.
- 청구일, 업체 지급기일, 근로자 임금일을 각각 보존한다. 회사 기본값은 새 초안에 적용하고 발송·수락 버전을 덮어쓰지 않는다.
- 단가 미정의 인원 협의를 금액이 확정된 계약 수락으로 만들지 않는다. 작업자·등급별 단가 또는 적용 가격표를 합의한 뒤 확정한다.
- 수락 시 업체 지급에는 예정만 연결한다. 실제 출역·비용·지급 없이 채무와 대불회수를 확정하지 않는다.
- 동일 요청을 재시도하거나 동시에 수락해도 현장·합의·지급 예정·채무를 중복 생성하지 않는다. 한쪽 연결 실패는 연결 중 상태로 재처리한다.
- 받은/보낸 요청은 최초 요청 방향을 유지한다. 사무소의 수정안은 원 요청업체가 수락할 수 있고 현재 제안자가 자기 제안을 수락하지 않는다.
- 이번 요청에서 바꾼 조건은 현장·회사 기본값을 자동 수정하지 않는다. 수락 후 변경은 적용일부터 새 합의로 남기고 이미 발생한 출역·청구·지급은 보존한다.
- 양쪽은 같은 수락 버전과 합의 확인본을 조회한다. 수락은 개인 근로계약 서명이나 실제 관제 배정·출역 완료가 아니다.
- 실제 실적을 기존 청구 준비에 연결하고 별도 인력 청구 초안은 만들지 않는다. 청구 생성 후 발송 전 수정·취소는 유지하며 발송한 문서 원본을 보존한다.
- 사무소가 보낸 청구는 요청업체의 받은 청구에서 수락 때 만든 정산 건을 연결 후보로 제시한다. 나중에 청구서를 받아도 이미 기록한 지급과 같은 채무를 유지한다.
- 청구액·상대 인정액·실제 지급·지급 통지·입금 확인을 구분한다. 같은 원문의 재전송·다른 수신 경로·부분 지급·반환이 중복 청구·채무·수금을 만들지 않는다.
- 기존 확정 금액과 과거 기록을 추정으로 재계산하거나 앱 수락 완료로 바꾸지 않는다.
- 실제 근로자 선정 전에도 등급별 단가표와 적용 규칙이 합의되면 수락할 수 있다. 최종 근무금액 미정과 단가 결정 규칙 미정을 구분한다.
- 일별 예상 세액과 지급 때의 소액부징수 결과를 구분한다. 같은 실제 지급을 화면 요청만 나눠 다른 세무 단위로 만들지 않는다.

- 자쿠는 자연어 의도와 입력을 기존 업무 경로에 연결하고 서버의 결과·다음 행동을 설명한다. 저장된 사실을 다시 묻거나 임금·세금·채무를 모델이 새로 계산하지 않는다.

- 진행 중인 거래를 이어받을 때 이전 근무·실제 지급·실제 공제·기초 미수/미지급을 구분해 받는다. 자료 부족을 0원이나 보험 미가입으로 바꾸지 않고, 기존 이력을 수정 없이 다시 저장해도 보존한다.

## 확인 항목

금액·경계값·중복·정정의 정답은 자동 QA 기준의 코드 검증으로 확인한다. 아래 기존 확인 문장은
체크 이력 연결을 위해 유지하되 대표가 금액을 다시 계산할 의무는 없다. 대표는 선택지가 자기 상황에
맞는지, 필요한 과거 이력을 넣을 수 있는지, 지급·청구 이유와 문서 상태를 이해할 수 있는지 확인한다.

- 견적 → 승인 견적에서 현장 등록 → 인력 청구 부가세 포함 또는 별도를 선택하면 생성한 현장의 정산 기본값에 같은 값이 남는다.
- 견적 → 동일 현장 등록을 다시 시도하면 같은 현장을 보여 주고 현장과 VAT 설정이 중복 생성되지 않는다.
- 현장 등록 → 임금 160,000원과 소개료 10%를 입력하면 임금 160,000원, 소개료 16,000원, 합계 176,000원이 보인다.
- 현장 조건 → 임금과 소개료 합계 160,000원에서 소개료 16,000원을 입력하면 임금 144,000원 대비 상한 초과 경고와 원값이 남고, 경고 후 발송·수락 및 필요한 사실이 있는 후속 계산을 진행할 수 있다.
- 거래조건 → 일반과세자로 등록된 사무소의 직업소개 거래도 소개료가 면세로 표시되고 대불원금은 매출과 분리된다.
