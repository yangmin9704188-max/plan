## 기획

### 누구를 위해

외주비·자재비·장비대·용역비를 지급하는 인력사무소와 인테리어·철거·설비 등 소규모 시공업체의 지급 담당자와 소장.

### 왜

지금은 청구서가 온 뒤의 지급 대기·진행·완료만 관리해서, 청구 전의 계약 회차·공수 차이·추가 공사와 협의 과정을 놓친다. 우리 기록으로 계산한 금액과 업체가 청구한 금액을 대조하고 합의한 금액으로 지급할 방법이 없다.

### 완성되면

- 출역·공수·납품·자재·장비·기성 근거로 지급 예상액을 계산한다
- 약정·내부 근거·받은 청구를 나란히 대조해 이번 인정액을 확정한다
- 청구서가 없어도 정액 총액·단가×실적·반복 정액·실비·내역·간편 거래를 등록하고, 회차·기간이 명확하면 예정 건이 자동으로 생긴다
- 추가 공사·증액·감액·협의 조정을 변경 요청과 합의로 반영한다
- 한 정산을 나눠 지급하거나 같은 업체의 여러 정산을 한 번에 지급하고, 이체내역서 등 증빙을 연결한다
- 선급금, 대불(다른 업체가 대신 지급한 작업자 임금), 유보금을 따로 관리한다

### 화면

정산센터 → 업체 지급 → 내부 산출 / 정산 검토 / 지급 관리

### 지켜야 할 규칙

- 내부 예상액, 원문 청구액, 최종 인정액, 실제 지급액을 각각 보존한다
- 자동 생성만으로 지급액이나 채무를 확정하지 않는다. 조건이 빠지면(예: 검수일을 모르는 '검수 완료 후 7일') 조건 대기로 남긴다
- 월별 일정은 지정한 기간만 생성한다
- 비교할 때 현장·기간·작업자 또는 품목·공수 또는 수량·약정 단가·세금 포함 기준을 맞추고, 근거가 부족하면 확인 필요로 남긴다
- 외주 약정 단가를 고객 청구단가나 작업자 임금으로 대신하지 않는다
- 정액 도급은 내부 공수가 달라도 계약금액을 자동으로 바꾸지 않는다
- 계약을 증액하면 최신 약정액과 회차 배분을 함께 고치고, 아직 배정하지 않은 금액은 미배정액으로 구분해 미지급으로 계산하지 않는다
- 협의로 금액을 조정하면 원문 청구액과 인정액을 함께 남기고, 회차 간 이동인지 최종 증감인지 구분해 가짜 잔액을 막는다
- 이미 지급한 기록은 덮어쓰지 않고, 감액 후 과지급도 숨기지 않는다
- 실제 지급 한 번을 여러 정산에 중복 합산하지 않는다
- 유보금은 감액과 구분하고, 무효·정정·반환은 각각 이유와 원본 이력을 남긴다
- 증빙 첨부만으로 송금 성공으로 표시하지 않는다
- 계산·금액 한도·중복 방지는 코드가 처리하고 인정액은 담당자가 확정한다. AI는 원문 정리·연결 후보·차이 설명만 돕는다
- 늦게 온 청구·수정본·여러 증빙이 붙어도 같은 거래의 채무를 다시 만들지 않는다
- 지급 업체와 현장 발주처는 다를 수 있고, 각각 우리 거래처·현장으로 연결한다
- Gmail·AI 연동 없이도 수동 입력·파일 첨부로 진행할 수 있다
- 인력 거래의 총액·세전 임금·소개료·대불원금은 현장·합의 조건과 같은 계산 결과를 사용하고 지급 화면에서 별도 세율·보험식을 만들지 않는다
- 사업주 보험료를 예산에 포함해도 기존 근로자 임금을 자동 감액하지 않고 약정된 비용 분담 또는 변경·협의로 처리한다
- 인력요청 수락과 늦게 온 메일·청구는 기존 약정·정산에 연결하며 별도 지급 대상을 중복 생성하지 않는다

### 이번에 안 하는 것

- Gmail·전용 수신주소·제출 링크·파일 분석을 통한 청구 접수 (받은 청구서 접수 기능의 범위)
- 자동 은행 송금
- 새 세금·보험 계산 엔진

## 확인 항목

- PAY-01: 정산센터 → 업체 지급 → 지급 계획 → 새 지급 계획에서 약정 3,000만 원과 500만·1,000만·500만 원의 세 회차를 저장 → 회차 보기와 새로고침 후 예정액 2,000만 원·미배정액 1,000만 원이 유지되고 확정 미지급에 자동 합산되지 않는지 확인한다.
- PAY-01: 지급 계획 → 새 지급 계획에서 지급 업체와 다른 발주처의 현장을 선택해 저장 → 선택한 업체·현장이 유지되고 거래처·현장 상세의 기존 발주처가 바뀌지 않는지 확인한다.
- PAY-01: 지급 계획 → 새 지급 계획에서 월별 정액의 시작월·종료월과 매월 31일을 지정해 저장 → 지정한 개월 수만 생성되고 31일이 없는 달에는 말일이 표시되는지 확인한다.
- PAY-01: 지급 계획 → 새 지급 계획에서 지급 조건을 검수 완료 후 7일로 입력하고 조건 충족일을 비워 저장 → 회차 보기에 조건 대기가 표시되고 임의의 지급일이 생기지 않는지 확인한다.
- PAY-01: 업체 지급 → 접수·검토에서 저장한 청구 초안을 열고 기존 정산 연결·변경 검토 → 거래와 정산 범위를 선택해 연결 → 연결 결과와 원문이 남고 별도 지급 청구가 중복 생성되지 않는지 확인한다.
- PAY-02: 업체 지급 → 내부 산출에서 현장·기간을 선택하고 공수·수량 내역을 열기 → 약정 단가와 출역·납품 등 근거를 확인할 수 있고 누락된 단가·근거가 0원으로 처리되지 않는지 확인한다.
- PAY-02: 업체 지급 → 정산 검토에서 같은 기간의 내부 20공수와 청구 21.5공수인 건을 열기 → 차이가 나는 작업일·공수·단가와 양쪽 근거를 대조할 수 있는지 확인한다.
- PAY-02: 업체 지급 → 정산 검토에서 청구서 없는 회차를 열고 약정·실적 근거로 금액을 확정 → 가짜 청구번호 없이 인정액과 지급 예정일이 지급 관리에 연결되는지 확인한다.
- PAY-03: 업체 지급 → 정산 검토에서 원문 청구 1,300만 원인 건을 열고 협의 금액 1,250만 원과 사유를 저장 → 재조회해 원문 금액·인정액·조정 이유가 함께 남고 지급 가능한 금액이 인정액을 따르는지 확인한다.
- PAY-03: 업체 지급 → 정산 검토 → 거래 상세에서 약정 3,000만 원을 3,500만 원으로 변경하고 두 회차에 200만·300만 원을 추가 배정 → 최신 약정액·회차 합계가 맞고 기존 지급 기록과 변경 전 이력이 유지되는지 확인한다.
- PAY-04: 업체 지급 → 지급 관리에서 한 정산 건의 일부 지급을 두 번 등록하고 각각 이체 증빙을 첨부 → 지급일·금액·증빙과 남은 지급액이 각각 저장되고 다시 열어 확인할 수 있는지 확인한다.
- PAY-04: 업체 지급 → 지급 관리에서 같은 업체의 여러 정산을 선택해 한 번의 지급으로 배분 → 실제 지급은 한 번만 집계되고 다른 업체 연결·배분액 초과·같은 지급의 중복 등록이 차단되는지 확인한다.
- PAY-04: 업체 지급 → 지급 관리에서 공급업체 선급금 300만 원 중 200만 원을 정산에 충당 → 선급 잔액 100만 원이 남고 작업자 임금 대불 내역과 섞이지 않는지 확인한다.
- PAY-04: 업체 지급 → 지급 관리에서 유보금과 해제 조건·기일을 설정한 뒤 상세를 열기 → 유보액이 인정액에서 감액되지 않고 현재 지급 가능한 금액과 구분되는지 확인한다.
- PAY-04: 업체 지급 → 지급 관리에서 일부 지급한 건의 인정액을 기지급액보다 작게 조정한 뒤 실제 반환을 등록 → 과지급과 반환 후 잔액이 맞고 원래 지급·정정·반환 이력이 보존되는지 확인한다.
- PAY-05: 업체 지급 → 내부 산출 / 정산 검토 / 지급 관리에서 같은 업체·현장·기간을 선택 → 같은 정산으로 이어지고 예정액·청구액·인정액·실제 지급액이 합계에 중복 반영되지 않는지 확인한다.
- PAY-05: 업체 지급 → 정산 검토에서 확정된 무청구 정산에 뒤늦은 청구·수정본을 연결하고 지급 관리에서 완료 내역을 다시 열기 → 지급 대상이 늘지 않고 미정리 금액의 이유와 기존 지급·증빙을 확인할 수 있는지 확인한다.
