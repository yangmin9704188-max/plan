## 기획

인력사무소와 인테리어·철거·설비 등 소규모 시공업체가 외주비·자재비·장비대·용역비를 지급할 때, 우리 기록으로 계산한 금액과 상대가 청구한 금액을 대조하고 합의한 금액을 지급할 수 있게 만든다. 청구서가 온 뒤의 지급 대기·진행·완료만 관리하면 청구 전의 계약 회차, 공수 차이, 추가 공사와 협의 과정을 놓치므로 거래와 회차·기간별 정산 건을 업무의 중심으로 둔다.

최종 화면은 `정산센터 → 업체 지급 → 내부 산출 / 정산 검토 / 지급 관리`로 구성한다. 내부 산출에서는 출역·공수·납품·자재·장비·기성 근거를 모아 예상액을 계산하고, 정산 검토에서는 약정·내부 근거·받은 청구를 대조해 이번 인정액을 확정하며, 지급 관리에서는 지급 일정·실제 지급·증빙·남은 금액을 관리한다. PAY-01 단계에서는 기존 `접수·검토 / 등록 청구·지급`에 `지급 계획` 탭을 추가하며, 최종 세 탭 통합은 PAY-05에서 진행한다.

청구서가 없어도 정액 총액·단가×실적·반복 정액·실비·내역·간편 거래를 등록할 수 있어야 한다. 명확한 회차·기간·지급 조건에서는 시스템이 예정 건을 생성하고, 소장·담당자는 부족한 조건과 실적을 보완한다. 자동 생성만으로 지급액이나 채무를 확정하지 않는다. 월별 일정은 지정한 기간만 생성하고, `검수 완료 후 7일`에서 검수일을 모르면 조건 대기로 남긴다. 지급 업체와 해당 현장의 발주처는 서로 다를 수 있으며, 각각 우리 회사의 거래처·현장으로 연결한다.

내부 예상액, 원문 청구액, 최종 정산 인정액, 실제 지급액을 각각 보존한다. 비교할 때 현장·대상 기간·작업자 또는 품목·공수 또는 수량·약정 단가·세금 포함 기준을 맞추고, 근거가 부족하면 확인 필요로 남긴다. 외주업체 약정 단가를 고객 청구단가나 작업자 임금으로 대신하지 않는다. 정액 도급은 약정 범위와 변경 합의가 기준이므로 내부 공수가 다르다는 이유로 계약금액을 자동 변경하지 않는다. LLM은 원문 정리·연결 후보·차이 설명을 도울 수 있지만 계산·금액 한도·중복 방지는 코드가 처리하고 인정액은 담당자가 확정한다.

추가 공사·자재·인건비 변동은 변경 요청과 확인된 합의로 반영한다. 계약 3,000만 원을 3,500만 원으로 증액하면 최신 약정액과 회차 배분을 함께 갱신하고, 아직 배정하지 않은 금액은 미배정액으로 구분한다. 미배정액을 확정 미지급으로 계산하지 않는다. 청구 1,300만 원을 1,250만 원으로 협의한 경우 원문과 인정액을 함께 남기고, 회차 간 이동인지 최종 증감인지 구분해 옛 계약금액에서 생기는 가짜 잔액을 막는다. 이미 지급한 기록은 덮어쓰지 않으며 감액 후 과지급도 숨기지 않는다.

실제 지급은 한 정산을 나눠 지급하거나 같은 업체의 여러 정산을 한 번에 지급할 수 있게 한다. 지급일·금액·수취 정보·이체내역서 등 증빙과 담당자 확인을 연결하고, 실제 지급 한 번을 여러 정산에 중복 합산하지 않는다. 공급업체 선급금과 다른 업체가 대신 지급한 작업자 임금인 대불은 별도로 관리한다. 유보금은 감액과 구분하고, 무효·정정·실제 반환은 각각의 이유와 원본 이력을 남긴다. 증빙 첨부만으로 은행의 송금 성공을 확인한 것으로 표시하지 않는다.

Gmail·전용 수신주소·제출 링크·파일 분석은 별도 청구 접수 기능의 범위다. 이 기능은 접수된 원문과 검토값을 기존 정산에 연결하거나 새 건·변경 검토로 적용한다. 청구서 없이 만든 건에 뒤늦은 청구가 붙거나 수정본·여러 증빙이 들어와도 같은 거래의 채무를 다시 만들지 않는다. Gmail이나 AI 연동을 기다리지 않고 수동 입력·파일 첨부로 진행할 수 있어야 한다. 기존 청구·부분 지급·무효·반환·작업자 대불·원본 연결을 보존하며, 자동 은행 송금과 새 세금·보험 엔진은 이번 범위에 포함하지 않는다.

PAY-01은 기존 [구현 PR #233](https://github.com/yangmin9704188-max/jakupan_office_web/pull/233)의 실제 브랜치에 연결하고, PAY-02~05는 아래 이름을 사용할 후속 개발 계획으로 둔다. 상세 업무·금액 경계는 [Office 개발계획](https://github.com/yangmin9704188-max/jakupan_office_web/blob/codex/office-vendor-payables-pay01-20261123/docs/OFFICE_VENDOR_PAYABLES_IMPLEMENTATION_PLAN.md)을 따른다. 아래 확인 항목은 각 단계가 화면에 반영된 뒤 확인할 기대 결과이며, PR 존재·병합만으로 기능 완료를 판단하지 않는다.

개발 중 PR을 분할·통합하거나 브랜치·저장소·작업 순서가 달라지면 이 파일의 개발 계획도 같은 작업에서 수정한다. 이 파일의 이름은 유지하고, 대표가 확인한 항목의 문장은 의미가 바뀌지 않는 한 보존한다.

## 확인 항목

- PAY-01: 정산센터 → 업체 지급 → 지급 계획 → 새 지급 계획에서 약정 3,000만 원과 500만·1,000만·500만 원의 세 회차를 저장 → 회차 보기와 새로고침 후 예정액 2,000만 원·미배정액 1,000만 원이 유지되고 확정 미지급에 자동 합산되지 않는지 확인한다.
- PAY-01: 지급 계획 → 새 지급 계획에서 지급 업체와 다른 발주처의 현장을 선택해 저장 → 선택한 업체·현장이 유지되고 거래처·현장 상세의 기존 발주처가 바뀌지 않는지 확인한다.
- PAY-01: 지급 계획 → 새 지급 계획에서 월별 정액의 시작월·종료월과 매월 31일을 지정해 저장 → 지정한 개월 수만 생성되고 31일이 없는 달에는 말일이 표시되는지 확인한다.
- PAY-01: 지급 계획 → 새 지급 계획에서 지급 조건을 검수 완료 후 7일로 입력하고 조건 충족일을 비워 저장 → 회차 보기에 조건 대기가 표시되고 임의의 지급일이 생기지 않는지 확인한다.
- PAY-01: 업체 지급 → 접수·검토에서 저장한 청구 초안을 열고 기존 정산 연결·변경 검토 → 거래와 정산 범위를 선택해 연결 → 연결 결과와 원문이 남고 별도 지급 청구가 중복 생성되지 않는지 확인한다.
- PAY-02: 업체 지급 → 내부 산출에서 현장·기간을 선택하고 공수·수량 내역을 열기 → 약정 단가와 출역·납품 등 근거를 확인할 수 있고 누락된 단가·근거가 0원으로 처리되지 않는지 확인한다.
- PAY-02: 업체 지급 → 정산 검토에서 같은 기간의 내부 20공수와 청구 21.5공수인 건을 열기 → 차이가 나는 작업일·공수·단가와 양쪽 근거를 대조할 수 있는지 확인한다.
- PAY-02: 업체 지급 → 정산 검토에서 청구서 없는 회차를 열고 약정·실적 근거로 금액을 확정 → 가짜 청구번호 없이 인정액과 지급 예정일이 지급 관리에 연결되는지 확인한다.
- PAY-03: 업체 지급 → 정산 검토에서 원문 청구 1,300만 원인 건을 열고 협의 금액 1,250만 원과 사유를 저장 → 재조회해 원문 금액·인정액·조정 이유가 함께 남고 지급 가능한 금액이 인정액을 따르는지 확인한다.
- PAY-03: 업체 지급 → 정산 검토 → 거래 상세에서 약정 3,000만 원을 3,500만 원으로 변경하고 두 회차에 200만·300만 원을 추가 배정 → 최신 약정액·회차 합계가 맞고 기존 지급 기록과 변경 전 이력이 유지되는지 확인한다.
- PAY-04: 업체 지급 → 지급 관리에서 한 정산 건의 일부 지급을 두 번 등록하고 각각 이체 증빙을 첨부 → 지급일·금액·증빙과 남은 지급액이 각각 저장되고 다시 열어 확인할 수 있는지 확인한다.
- PAY-04: 업체 지급 → 지급 관리에서 같은 업체의 여러 정산을 선택해 한 번의 지급으로 배분 → 실제 지급은 한 번만 집계되고 다른 업체 연결·배분액 초과·같은 지급의 중복 등록이 차단되는지 확인한다.
- PAY-04: 업체 지급 → 지급 관리에서 공급업체 선급금 300만 원 중 200만 원을 정산에 충당 → 선급 잔액 100만 원이 남고 작업자 임금 대불 내역과 섞이지 않는지 확인한다.
- PAY-04: 업체 지급 → 지급 관리에서 유보금과 해제 조건·기일을 설정한 뒤 상세를 열기 → 유보액이 인정액에서 감액되지 않고 현재 지급 가능한 금액과 구분되는지 확인한다.
- PAY-04: 업체 지급 → 지급 관리에서 일부 지급한 건의 인정액을 기지급액보다 작게 조정한 뒤 실제 반환을 등록 → 과지급과 반환 후 잔액이 맞고 원래 지급·정정·반환 이력이 보존되는지 확인한다.
- PAY-05: 업체 지급 → 내부 산출 / 정산 검토 / 지급 관리에서 같은 업체·현장·기간을 선택 → 같은 정산으로 이어지고 예정액·청구액·인정액·실제 지급액이 합계에 중복 반영되지 않는지 확인한다.
- PAY-05: 업체 지급 → 정산 검토에서 확정된 무청구 정산에 뒤늦은 청구·수정본을 연결하고 지급 관리에서 완료 내역을 다시 열기 → 지급 대상이 늘지 않고 미정리 금액의 이유와 기존 지급·증빙을 확인할 수 있는지 확인한다.
