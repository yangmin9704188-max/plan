## 기획

### 누구를 위해

거래처에서 청구서를 받아 지급을 처리하는 인력사무소·소규모 시공업체의 담당자.

### 왜

청구 내용이 이메일, PDF, 사진, 한글·엑셀 문서에 흩어져 있어 담당자가 매번 손으로 옮겨 적는다. 어느 업체가 어느 현장 일로 얼마를 언제까지 청구했는지 원문과 함께 확인하기 어렵다.

### 완성되면

- PDF·이미지·HWP·HWPX·XLSX 청구 자료를 직접 첨부, 거래처 제출 링크, 작업판 전용 수신주소, Gmail로 한 곳에 접수한다
- 업체명·청구번호·금액이 빠진 자료도 미완성 초안으로 보관하고 나중에 채운다
- 고른 자료만 AI로 분석해 업체·현장·금액·기한·품목을 원문 위치·근거와 함께 제안받는다
- 제안과 원문을 비교·수정한 뒤 확인하면 기존 업체 지급에 등록된다
- 여러 원본을 한 청구로 묶거나, 한 원본에서 여러 청구 초안을 만든다
- 기존 청구와 겹치거나 수정본일 가능성을 알려준다

### 화면

원본 접수 → 초안 저장 → (선택) AI 분석 → 원문과 비교·수정 → 확인 후 업체 지급에 등록

### 지켜야 할 규칙

- AI는 담당자가 고른 PDF·이미지·본문만 분석한다. 메일 후보 수집·검색·원문 열람만으로 AI 분석이나 사용량 차감이 시작되지 않는다
- 빠졌거나 불확실한 값은 추정으로 채우지 않고 확인할 내용으로 남긴다
- 담당자가 직접 고친 값은 AI가 덮어쓰지 않고, 고른 제안만 적용한다
- 공급가액·세액·총액·품목 계산은 코드로 검산한다
- 원문 청구번호와 내부 관리번호를 구분한다
- 초안 제외·첨부 해제가 원본 삭제로 이어지지 않고, 등록 당시의 원본·내용·담당자 확인 기록을 보존한다
- AI 분석과 지급 대상 등록은 별도 행동이다. 분석·초안 저장·등록만으로 송금, 실제 지급액, 작업자 정산, 세금 기록이 바뀌지 않는다
- 문서에 적힌 기지급액을 실제 지급 기록으로 만들지 않아 이중 차감을 막는다
- 같은 요청을 다시 보내도 청구·AI 호출·사용량이 중복으로 생기지 않는다
- AI를 쓸 수 없거나 한도를 넘어도 수동 입력·검토는 계속할 수 있다
- 거래처 제출 링크는 가입 없이 제출하게 하되 내부 청구·다른 거래처 자료·지급 권한은 보이지 않는다
- Gmail은 지정한 라벨·발신자·제목 조건의 후보만 모으고, 고른 메일만 본문·첨부를 가져온다. 같은 대화의 다른 답장은 자동으로 포함하지 않는다
- 문서 변환 실패·암호·손상·표 누락은 성공으로 감추지 않는다
- AI 모델의 이미지 처리·한국어 판독 품질·비용 정책은 따로 확인하기 전까지 사용 가능으로 보지 않는다
- 전용 수신주소·Gmail·첨부·제출 링크는 같은 원본·초안 경로를 사용하고, 약정·인정액·실제 지급은 기존 업체 지급 경로에 연결한다
- 원문에서 추출한 사업자번호·보험·부가세는 입력 제안으로 보존한다. 기존 거래처·계약 정보나 법정 계산을 메일 내용만으로 덮어쓰지 않는다

### 이번에 안 하는 것

- 송금, 실제 지급, 작업자 정산, 세금 기록 처리 (업체 지급 기능의 범위)
- Gmail 공개 출시 준비 (이 기능의 선행 조건이 아님)

## 확인 항목

- 정산센터 → 업체 지급 → 접수·검토 → 새 청구 초안 → 원본을 첨부하고 업체명·청구번호·금액을 비운 채 초안 저장 → 새로고침 후 초안 열기에서 빈 값과 원본이 그대로 남는지
- 청구 원본 → PDF · JPEG · PNG 첨부 → 각 파일의 미리보기와 원본 다운로드 → 올린 문서의 내용과 내려받은 원본이 일치하는지
- 청구 원본 → 받은 서류 선택 또는 다른 초안의 원본 선택 → 여러 원본을 연결하고 초안 저장 → 다시 열어도 선택한 원본이 한 초안에 연결되어 있는지
- 청구 원본에서 일부 파일 체크 → 선택 원본으로 새 초안 → 선택한 원본을 연결한 새 초안이 생기고 기존 초안과 원본이 보존되는지
- 초안 제외 → 접수 목록에서 제외 상태 선택 → 초안 열기 → 초안 복원 → 기존 입력과 원본을 유지한 채 다시 검토할 수 있는지
- 청구 총액과 품목 합계를 다르게 입력하고 초안 저장 → 확인할 사유가 보이고 지급 대상 등록이 막히는지, 금액을 맞추면 그 사유가 해소되는지
- 원문 번호가 없는 초안에 업체·금액·확인 근거·메모 입력 → 확인 후 지급 대상으로 등록 → 등록 청구·지급에서 원문 번호와 내부 관리번호가 구분되고 실제 지급액은 자동으로 늘지 않는지
- 등록한 초안을 다시 열어 등록된 지급 상세 열기 → 새로고침해도 같은 청구 한 건으로 연결되고 승인 당시 입력·원본·확인 기록을 확인할 수 있는지
- 청구 원본에서 일부 파일 체크 → AI로 청구 입력 채우기 → 분석할 자료 선택 → 선택한 자료 AI 분석 → 고른 자료만 분석 대상으로 표시되는지
- 초안의 원본 본문 입력 → 분석할 자료 선택에서 원본 본문 포함 체크 → 저장 후 선택한 자료 AI 분석 → 본문에서 추출한 값과 인용 근거를 볼 수 있는지
- AI 분석 이력 → 분석 결과 보기 → 현재 입력·AI 제안·원문 근거를 비교하고, 누락값·합계 불일치·확인할 내용을 구분할 수 있는지
- 수동으로 고친 초안에서 AI 결과의 일부 항목만 체크 → 선택한 제안값 초안에 적용 → 고른 값만 바뀌고 선택하지 않은 수동 입력과 기존 지급 기록은 유지되는지
- 중복 청구·수정본 가능성이 표시된 분석 결과 → 등록 청구·지급 보기 → 기존 청구액·실제 지급·잔액을 비교할 수 있고 AI 적용만으로 새 지급이나 기지급액의 이중 차감이 생기지 않는지
- AI 분석을 사용할 수 없는 초안 → 분석 가능 여부 다시 확인 → 사용할 수 없는 사유를 보여주면서 직접 입력·초안 저장·수동 등록은 계속 가능한지
- 업체 지급의 거래처 제출 링크 화면 → 현장을 지정하여 링크 발급·복사 → 다른 브라우저에서 열어 가입 없이 청구 자료를 제출할 수 있는지
- 거래처 제출 완료 화면에서 접수 결과 확인 → Office 접수·검토에서 해당 건 열기 → 지정한 회사·현장의 자료만 들어오고 외부 화면에는 내부 청구나 다른 제출자의 자료가 보이지 않는지
- 거래처 제출 링크 화면에서 링크 철회 또는 만료 설정 → 해당 링크를 다시 열어 제출 시도 → 새 자료를 받을 수 없다는 안내가 보이고 이미 접수한 자료는 보존되는지
- 업체 지급의 전용 수신주소 설정 화면 → 발급된 주소로 청구 메일 전송 → 접수·검토에서 올바른 회사의 본문·첨부가 분석 전 상태로 들어오고 자동 지급 등록은 되지 않는지
- 전용 수신주소로 접수한 건의 처리 내역 열기 → 수신 처리 재시도 뒤에도 같은 메일이 중복 접수되지 않고 실패한 첨부는 사유와 보완 방법이 표시되는지
- 업체 지급의 Gmail 수신 설정 → 연결 동의와 청구 라벨·수신 조건 지정 → 후보 목록에서 조건에 맞는 제목·발신자·수신 시각만 먼저 보이고 분석 전 상태로 남는지
- Gmail 후보에서 메일 한 건의 원문 확인 → 원문만 닫고 후보 목록으로 복귀 → AI 분석이 시작되거나 분석 이력이 추가되지 않는지
- Gmail 후보 여러 건 중 일부 선택 → 선택한 메일 AI 분석 → 선택한 메일의 본문·첨부만 초안에 연결되고 미선택 메일과 같은 대화의 다른 답장은 포함되지 않는지
- Gmail 수신 설정에서 수신 중지 → 새 청구 메일 도착 후 후보 목록 확인 → 새 수집과 아직 시작하지 않은 분석이 멈추고 기존 자료·발신 설정은 유지되는지
- 청구 원본에 HWP와 HWPX를 각각 첨부 → 변환 결과와 AI 분석 결과 열기 → 업체·내역·합계와 원문 페이지 근거를 확인하거나 지원 불가 사유를 분명히 볼 수 있는지
- 여러 시트가 있는 XLSX를 첨부 → 분석 결과와 원문 시트·셀 근거 열기 → 시트별 내역과 합계가 누락 없이 보이거나 확인할 시트가 표시되는지
- 암호가 걸리거나 손상된 문서를 첨부 → 처리 결과 열기 → 성공으로 표시되지 않고 재제출·수동 보완 방법을 안내하는지
