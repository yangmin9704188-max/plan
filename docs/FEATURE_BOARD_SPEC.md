# 작업판 개발 대시보드 — 제품 명세

## 목적

GPT와 대화로 정한 **기획 + 개발 계획**을 잊지 않고, GitHub PR 진행을 보면서, 대표가 **어떤 화면을 눌러 무엇을 확인해야 하는지** 한 곳에서 본다.

## 역할

| 누가 | 무엇을 | 어디에 |
| --- | --- | --- |
| GPT | 기획, 개발 계획(Step·브랜치), 제품, 확인 항목 작성 | GitHub `features/*.md` |
| 대시보드 | 기능 파일과 PR 상태를 읽어서 표시 (읽기 전용) | — |
| 대표 | 확인 항목 통과/문제(+메모), 완료 처리 | 로컬 `data/state.json` |

대표는 기능을 등록·수정·삭제하지 않는다. 화면에 그런 버튼이 없다.

## 화면

- 메뉴 두 개: **대시보드**(미완료), **완료**
- 상단: 기능 파일 위치, 마지막 조회 시각, **새로고침** 버튼 (자동 조회 없음. 페이지를 처음 열 때만 한 번 읽음)
- 제품 탭(기능 하나가 여러 제품에 속할 수 있음), 검색
- 기능 한 줄 → 펼치면 3단계
  1. **기획**: 자유 텍스트
  2. **개발**: `Step N — 제목`, 브랜치·저장소, PR 번호 링크, GitHub 상태
  3. **내 확인**: 항목마다 `통과` / `문제`(+메모). 같은 버튼을 다시 누르면 미확인으로 돌아감
- **완료 처리**: 대표가 누르면 완료 메뉴로 이동. 통과 안 된 항목이 있으면 한 번 묻는다. 완료 메뉴에서 되돌릴 수 있다.

## 상태

- 기능: `미완료` / `완료` (대표만 바꿈)
- Step PR (GitHub 그대로): `브랜치 미연결` / `PR 대기` / `초안` / `열림` / `병합` / `미병합 종료` / `조회 불가`
- 확인 항목: `미확인` / `통과` / `문제`

## 성능

- 완료된 기능은 새로고침 때 PR을 조회하지 않고, 완료 메뉴를 열 때만 목록을 불러온다.
- 변경되지 않은 기능 파일(같은 sha)은 다시 내려받지 않는다.
- 접힌 기능은 본문을 그리지 않는다.

## 연동

- `GET /api/board?view=active|done` — 마지막 조회 결과 (없으면 한 번 조회)
- `POST /api/refresh?view=active|done` — GitHub에서 다시 읽기
- `PATCH /api/features/:id/checks/:checkId` — `{ "result": "pass" | "issue" | "pending", "note": "..." }`
- `POST /api/features/:id/complete`, `POST /api/features/:id/reopen`
- `GET /api/health`
- 로컬(`127.0.0.1`)에서만 접근 가능. GitHub에는 쓰지 않는다.

## 명시적으로 제외

- 화면에서 기획 작성/수정/삭제, 자동 주기 조회, PR 자동 병합, 병합으로 완료 추론
- 다중 사용자, 공개 배포, GitHub 쓰기 권한, ROVENTRA 연동
