# 작업판 개발 진행표 — 제품 명세 (MVP)

## 목적

기능 하나의 **최종 기획 → 개발계획/PR 분할 → GitHub PR 진행 → 대표 직접 확인**을 한 화면에서 확인한다. 에이전트가 보드에 진행 상태를 중복 보고하게 만들지 않는다.

## 불변 조건

1. 최초 기획 등록과 사용자의 최종 확인만 수동 상태로 저장한다.
2. PR은 GitHub에서 읽기만 한다. 제목 유사도로 자동 매칭하지 않는다. `owner/repo` + 정확한 브랜치 또는 PR 번호를 입력한다.
3. 병합된 PR은 실제 배포, 검증, 대표 확인 완료를 뜻하지 않는다.
4. GitHub 인증 오류/네트워크 오류는 `조회 불가`로 표시한다. PR이 없다고 간주하지 않는다.
5. 기획서와 개발계획서는 GitHub 원문 링크 또는 사이트에 붙여넣은 텍스트로 등록할 수 있다.
6. 사용자 체크리스트는 `미확인 / 통과 / 문제` 및 선택적 메모로 관리한다.
7. 여러 제품과 여러 GitHub 저장소의 PR을 하나의 기능에 연결할 수 있다.

## 화면

- 요약: 등록 기능 수, 병합된 PR 수, 사용자 확인 필요 수
- 좌측: 제품별 필터, 검색, 기능별 PR 현황 및 확인 진행률
- 우측: 최종 기획/개발계획, PR별 상태와 GitHub 링크, 사용자 체크리스트
- 등록/수정 모달: 기획, PR 계획, 체크리스트 최초 생성 및 필요 시 수정

## 상태

- PR: `연결 대기 / 초안 / 열림 / 병합 / 미병합 종료 / 조회 불가` (GitHub 읽기 전용)
- 사용자 확인: `미확인 / 통과 / 문제` (대표 입력)
- 기능 요약: `기획 중 / 개발 준비 / PR 진행 중 / 내 확인 대기 / 확인 문제 / 내 확인 완료` (두 축을 기반으로 화면에서 계산, 별도 워크플로 상태 없음)

## 명시적으로 제외

- 에이전트 세션·실행·핸드오프 기록, 자동 작업 지시, PR 자동 병합, 검증 PASS 자동 기록
- ROVENTRA MCP, Capability DB, Task/Run 계층, 의존성 그래프, 릴리스 오케스트레이터
- 공개 배포, 다중 사용자 인증, 외부 공개 API, GitHub 쓰기 권한

## 연동

- REST API는 로컬에서만 접근 가능 (`127.0.0.1`).
- `GET /api/features`, `POST /api/features`, `PATCH /api/features/:id`, `DELETE /api/features/:id`
- `PATCH /api/features/:id/checks/:checkId`
- `GET /api/progress` (2분 캐시), `GET /api/progress?refresh=1` (강제 새로고침)
- GitHub API: Pull requests Read-only. 비공개 저장소는 서버에 `GITHUB_TOKEN` 필요.
- 웹브라우저의 ChatGPT 세션에서는 사용자의 localhost API에 직접 접근할 수 없을 수 있다. 이 경우 사용자가 직접 등록하거나 로컬 에이전트가 POST할 수 있다.
